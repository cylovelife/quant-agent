# quant-agent — 双轨投资助手（短线低吸 + 长期价值）

跨市场（A股 / 港股 / 美股 / 场内ETF / 场外基金）的投资筛选 Agent，**不是一次写完就稳定的代码，而是每天拿次日实盘数据自我校验、持续修正的迭代系统**。

两条互相独立的轨道，共用同一套行情抓取与缓存：

| 轨道 | 回答的问题 | 持有周期 | 验证节奏 | 主要依据 |
|---|---|---|---|---|
| **短线轨** `short` | 明天买什么、明天卖什么 | 3~8 个交易日 | 次日即可验证 | 价格位置、量能、离场期望值 |
| **长期轨** `long` | 现在值得长期拿什么 | 数月至数年 | 5/20/60/120/250 交易日 | 宏观、公司质量、估值、行业 |

> ⚠️ 仅供研究学习，不构成投资建议。历史回测不代表未来，短线低吸存在接飞刀风险，请控制仓位、独立决策。

## 快速开始

```bash
python run.py                    # 完整：短线 + 长期 + 报告
python run.py --mode short       # 只跑短线低吸轨
python run.py --mode long        # 只跑长期价值轨
python run.py --quick            # 快速：减少短线回测标的数
python run.py --no-replay        # 跳过长期历史回放（省约 1 分钟）
python run.py --no-cache         # 忽略阶段缓存，强制全部重算（用于验证缓存一致性）
python run.py --no-eval          # 跳过昨日短线复盘
python run.py --market cn,etf    # 短线轨只跑指定市场（cn/etf/hk/us/fund）
python run.py --db-stats         # 落盘概览：各表行数 / 行情覆盖 / 数据源健康 / 资金流覆盖 / 指数序列窗口 / ML 结论
python run.py --csc-probe        # 自检中信建投数据源连通性
python run.py --akshare-probe    # 自检 akshare 数据源连通性与字段口径（不写库）
python run.py --fund-flow        # 只抓当日个股资金流截面并落库（约 15s，可重复跑）
python run.py --new-sources      # 跑全部 Phase 1 新数据源：资金流 + 龙虎榜/两融/解禁/退市清单
python run.py --spot-probe       # 逐档实测 ETF/港股/美股现货降级链（只读，约 90s）
python run.py --ml-eval          # 走前 ML 验证：样本外预测 vs 规则分（只读，不接入评分）
python run.py --brief           # 报告只留操作清单与结论（完整版另存 report_*.full.*）
python run.py --full            # 强制完整版报告，覆盖 config.json 的 report.brief
```

**报告默认精简版**（`config.json` 的 `report.brief: true`）：`report_YYYY-MM-DD.*`
只放「今日操作清单 + 两处结论 + 长期轨候选」——一屏看完、5 分钟能执行完。
完整证据（因子检验 / 离场规则体检 / 行业排名 / 指数估值）同期另存
`report_YYYY-MM-DD.full.*`，需要复查口径时再翻。

环境变量可覆盖配置（优先级高于 `config.json`）：

| 变量 | 作用 |
|---|---|
| `QUANT_STORE=file` | 整体关闭 SQLite 落盘，完全走文件缓存 |
| `QUANT_DB=<path>` | 换一个库文件 |
| `QUANT_KLINE_TTL_H=4` | 行情复用窗口（小时） |
| `QUANT_CSC=off` | 关闭中信建投数据源 |
| `QUANT_AKSHARE=off` | 关闭 akshare 数据源（资金流采集整体跳过） |

依赖：`pip install requests pandas numpy curl_cffi scikit-learn`
（`scikit-learn` 只被 `--ml-eval` 用到，不装不影响主流程）。
`akshare` 是**可选依赖**：只被资金流采集用到，不装时该数据源自动跳过、
主流程照常走完（`--akshare-probe` 会告诉你是没装还是连不上）。

### 耗时与「看起来卡死」的排查

实测单次 `--mode all`（64 只标的、5470 笔路径）：**冷启动约 6 分钟**，
K 线与参数未变时那三段重计算会命中缓存，**降到约 1~2 分钟**。

行情侧另有一层复用：抓过的 K 线落进 `state/quant.db`，同一交易日内重跑直接读库、
不再发请求（实测 10 只标的的抓取段从 5s 降到 0s；详见「数据落盘」章节）。所以
「调参—重跑—看报告」这种同日内反复运行，第二次起基本只剩纯 CPU 那一段。

耗时集中在三段纯 CPU 计算，合计约占 70%：

| 阶段 | 冷启耗时 | 说明 |
|---|---|---|
| 离场模型标定 `fit_exit_model` | ≈155s | 面板标定 + 样本外验证 |
| 离场规则体检 `parameter_scan` | ≈60s | 5315 笔信号的参数扫描 |
| 短线模型选型 `select_short` | ≈48s | 36 组规则 × 3 折 walk-forward |

**如果一次运行「很久不结束」，先分清三种情况**（日志里能直接看出来）：

1. **被冻住**（最常见）：机器休眠/合盖会把进程挂起，`ps` 里仍显示高 CPU、`etime` 一直涨，
   但**日志时间戳停止前进**。历史日志里出现过 25 / 74 / 253 / 712 / 1122 分钟的空洞，
   全是休眠造成的，唤醒后 1 秒内算完。长任务一律用 `caffeinate -i` 包裹：
   ```bash
   caffeinate -i python -u run.py --mode all
   ```
2. **在算**：日志里每 20 秒有一行「… 仍在计算（已 Xs）」心跳。
   有心跳就是在算，只是慢；日志停住才是真卡住。
3. **数据源变慢/不可用**：日志里会看到「抓取K线 i/n（已 Xs）」逐标的进度；
   若某市场累计抓取耗时超过预算（默认 180s，`config.fetch_budget_sec` 可调），
   会打印「已超预算，剩余标的直接跳过」并继续往下走，不会无限等。
4. **真卡住**：进度与心跳都停住，且 `ps` 显示 CPU 接近 100% 持续数分钟
   → 用 `sample <pid> 5` 采样调用栈。

> 为什么按**累计耗时**而不是按失败次数熔断数据源：限流是瞬时的，连续几只失败后往往
> 又能取到。按次数熔断会把限流误判成源故障，直接掐掉整个市场的行情——实测后果是
> 某次运行里滚动面板从 63 只掉到 6 只，报告数字整体失真，而且因为是「跳过」而非
> 「报错」，不会有任何异常提示。耗时预算只拦真正的「源不可用」：单只标的要依次试
> 3 个源 + 重试 3 次，最坏 ≈153s，12 只就是半小时的静默等待。

> 缓存是**内容寻址**的：键由 K 线内容指纹（含全表哈希，能捕捉除权导致的历史重算）
> 与参数签名共同决定。任何输入变化都会换 key，最坏情况只是不命中、退化成一次完整计算，
> 不存在「把旧结果喂给新数据」。命中与未命中都会写日志，不会静默复用。
> `--no-cache` 可强制重算；等价性由 `tests/verify_phase_cache.py` 独立验证
> （**不要用整份报告比对缓存**——候选池来自实时快照，两次运行标的不同属数据漂移）。

| 个股融资融券 | 交易所官网 sse / szse（经 akshare） | **T+1 公布**，所以先解析「最近已公布日」再抓；可回补 |

### 现货降级链不是「等价替换」（实测）

ETF/港股列表的链是 **东财 clist → 腾讯核心池 → 新浪全量**。三档都用 `data_health`
与 `rank_snapshot.src` 留痕，`--spot-probe` 可逐档实测（2026-09-30 实测）：

| 档 | ETF | 港股 | 美股 | 耗时 |
|---|---|---|---|---|
| 东财 clist | 空 | 空 | 空 | ~20s（每次失败） |
| 腾讯核心池 | **62 只** | **47 只** | 48 只 | ~1s |
| 新浪全量 | **1693 只** | **2806 只** | 无可用源 | 5.9s / 21.6s |

东财在本机成功率只有 9%~15%，所以**多数日子的候选池实际是腾讯那份静态核心池
（62 / 47 只）**，而全市场有 1693 / 2811 只。这不会报错、报告也看不出异常——
只是「跌幅居前的活跃标的」被悄悄换成了「这份固定名单里跌得最多的」。
是否把新浪提到腾讯之前（改 `datasource.spot_tier_order`）会改变每日候选池，
属于策略口径变更，需单独确认后再动。

### 海外出口 IP 对国内数据源的影响（实测）

本机 VPN 是 TUN 模式、默认路由走 `utun0`，**出口 IP 在境外**（实测日本东京）。
后果是**国内站点也看到海外 IP**，部分子系统按地域/IP 风控直接拒连：

| 上游 | 实测 | 受影响的数据 |
|---|---|---|
| 东财 **push 集群** `push2his` / `*.push2` / `push2delay` | ❌ 连接被 reset / 502（curl、requests 直连、curl_cffi **三种客户端全失败**） | 个股资金流日线、ETF/港/美现货列表（东财 clist 长期成功率仅 9%~15%） |
| 东财 `datacenter-web` | ✅ 正常 | 龙虎榜、解禁、F10 财报 |
| 交易所官网 sse / szse / bse | ✅ 正常 | 两融、退市名单 |
| 新浪 / 腾讯 | ✅ 正常 | ETF 与港股清单、A 股行情（`tencent_quote_list` 100%） |

所以**资金流的源刻意选了同花顺而不是东财**：东财那条链路在本机是坏的，
拿它当主源等于把一个已知不可用的依赖写进架构。完整实测矩阵见
`docs/research/phase1_data_channel_probe.md`。

### 中信建投（CSC）SkillHub 数据源

在原有源之外接入了中信建投证券的数据接口，补上三处原本没有的能力：

| 用途 | 接口 | 说明 |
|---|---|---|
| **财务兜底** | `/info/f10/finance/more?ids=gjzb` | 东财 F10 是原来唯一的财报源，一旦限流整条长期轨只能吃旧缓存；现在有了第二条链 |
| **指数估值** | `/info/etf/index/list`、`/valuation` | ETF 原本**完全没有估值数据**（腾讯行情接口对 ETF 的 PE/PB 字段为空），这里给其跟踪指数的 PE/PB 与历史分位，并对分位最低的几个拉 5 年序列 |
| **行业相对位置** | `/info/f10/finance/industryRank` | 个股在所属行业的指标排名与行业均值，用来区分「行业整体便宜」与「个股自身便宜」 |

启用条件：`CSC_API_KEY` 可从环境变量读到，或存在于
`~/.workbuddy/skills/<skill_id>/.env`（`QUANT_CSC=off` 可整体关闭）。用
`python run.py --csc-probe` 自检连通性。

**公告日的坑（必须知道）**：中信建投的财务关键指标接口**不返回公告日**，而本项目
历史回放的「无前视」保证依赖公告日对齐。这里的处理是拿**法定披露截止日**
（年报次年 4-30、一季报/年报 4-30、中报 8-31、三季报 10-31）作为公告日的
**保守上界**，来源标记为 `statutory_deadline` 与东财的真实公告日 `disclosure` 区分；
落库时**真实公告日优先，永不被代理值覆盖**。

方向是「宁可晚算、不可早算」——代理日只会晚于真实公告日，所以不会前视；代价是
回放时会少掉一段本来可用的窗口。**这是降级，不是等价替换**，因此凡是用到降级财务的
标的都会出现在报告开头的「数据完整性提示」里。

> 两处**刻意不做**的接入：指数估值与行业排名目前只作**展示**，不进入六维评分。
> 长期轨的 120 日 IC=+0.155（t=5.24）是在「没有这两项输入」的条件下验证出来的，
> 中途往评分里塞新因子会让已成立的结论失效、收益无法归因。要接入必须先做一次
> 完整的前向验证（回放 + 样本外 + 尾部守卫），而不是「加上去看着更全」。

**指数分位必须连成立年限一起看**（实测踩到的坑）：按 PE 分位升序取最低的几个，
系统性地会落到**成立时间很短的新指数**上——样本窗口短，分位天然贴近边界。实测
上证科创板综合指数 PE=141.36 却挂着 4.26% 的 PE 分位（PB 分位 83.31%），把这一行
读成「便宜」会直接读反。所以：

- 指数列表的 `publishDate` 会落库（`index_snapshot.publish_date`），报告表格里加
  **成立** 列，成立不足 `csc_index_min_years`（默认 5 年）的带 ⚠ 并单独提示。
  这个阈值**只影响标注**，不再用来过滤取数——早期版本用它预先筛掉新指数，
  结果最便宜的那几个指数一条曲线都拿不到；现在由窗口自适应兜住（见下）；
- 报告里把该指数**实际落库的序列窗口**也列出来，因为窗口是被动降级的结果（见下）。

**`rc=102` 不是限流，是「窗口超出可用历史」**（实测取证）：上游对「请求窗口长于
该指数成立年限」的请求不回空数组，而是直接返回 `rc=102`。证据链：

| 指数 | 成立 | 1y | 3y | 5y | 10y | all |
|---|---|---|---|---|---|---|
| 000680 上证科创板综合 | 1.7y | 242 点 | rc102 | rc102 | rc102 | rc102 |
| 000698 上证科创板100 | 3.0y | 242 点 | 725 点 | rc102 | rc102 | rc102 |
| 000300 沪深300 | 21.5y | 242 点 | 725 点 | 406 点 | 488 点 | 263 点 |

另外对老指数连发 12 次，0 异常。所以这不是限流，重试只是白跑。处置：

- `CscError` 带 `rc` / `retryable` 两个字段做**失败分类**：只有网络异常与
  429/5xx 归入可重试（默认 2 次、指数退避 + 抖动），401/400/403 与 `rc=102`
  一次即返回——把权限问题和确定性结果伪装成「网络抖动」是更糟的错；
- `index_valuation` 做**窗口自适应降级**：5y → 3y → 1y 依次尝试，拿到就用。
  这不是重试（参数变了，数据也不同），实际窗口以 `_window_used` 返回并落库到
  `index_valuation.window_days`。不记窗口的话，库里一条 1 年序列和
  一条 5 年序列长得一模一样；
- 于是新指数也能拿到一段自己的曲线（000680 拿到 1y/242 点、000698 拿到 3y/725 点），
  不再像早期版本那样被成立年限过滤掉、一条都拿不到。

**全收益版 / 价格版是同一个敞口**：`000680 上证科创板综合指数` 与
`000681 上证科创板综合价格指数` 的成分股完全相同，估值五项（PE/PB/PE 分位/PB 分位/
ROE/股息率）与成立日逐一相同，只有 `change1Year`（20.61% vs 20.23%）和
`maxDrawdown1Year` 有微小差——那点差正是分红贡献，是「全收益 vs 价格」的特征差。
判据因此不是名字相似，而是**估值五项 + 成立日全等**。处置是**标注而非删除**：
两个代码各有 ETF 跟踪，删掉任何一个都会让「我的 ETF 跟的是哪一个」失去答案；
报告里合并成一行、代码栏并列显示，并在补历史序列时只取代表行，省一次请求。

## 数据落盘（SQLite）

中间数据统一落在 `state/quant.db`（SQLite），文件缓存保留为并行路径，两者不冲突。

**为什么是 SQLite 而不是 MySQL**：这是单机、单用户、单进程写入的场景——跑一次、
抓一次、算一次、写一次。MySQL 要常驻服务、端口、账号与备份策略，换来的并发写能力
这里一点用不上；SQLite 是标准库自带、单文件、零运维，还能跟着 `state/` 一起备份或
删掉重建。表结构只用标准 SQL 类型，将来真要迁 MySQL，改的是连接串而不是 schema。

| 表 | 内容 | 主键 |
|---|---|---|
| `kline` | 行情（`adjust` 区分 `qfq` 前复权 / `raw` 不复权；`nav` 基金净值为**预留档位，当前无写入方**） | market+code+adjust+date |
| `kline_meta` | 每只标的的日期边界、行数、最近抓取时间 | market+code+adjust |
| `rank_snapshot` | 每日榜单快照（跌幅榜/成交额榜/ETF 池） | market+board+snap_date+code |
| `fin_metrics` | 财务关键指标 + 原始 payload + **公告日来源分级** | market+code+report_date |
| `index_snapshot` / `index_valuation` | 指数估值截面 / 历史序列（含 `publish_date` 成立日、`window_days` 实际请求窗口） | index+market(+metric+date) |
| `industry_rank` | 个股行业排名与行业均值 | code+metric+report_date |
| `fund_flow` | 个股资金流截面（金额统一为**元**；上游只给当日快照，**逐日累积、无法回补**） | market+code+flow_date |
| `lhb` / `lhb_inst` | 龙虎榜明细（同一股票同一天多个上榜原因各占一行）/ 机构买卖统计 | trade_date+code(+reason) |
| `margin` | 个股融资融券（金额=元、数量=股；三家交易所披露字段不同，缺就写 NULL） | trade_date+code |
| `restriction` | 限售解禁（数量=股、市值=元；`ratio_of_float` 是**小数**，与龙虎榜那几个百分数方向相反） | code+release_date+share_type |
| `delisted` | 退市标的清单（主键含退市日：A 股代码存在被回收再用的可能） | code+delist_date |
| `macro_snapshot` | 每日宏观分/建议仓位区间/风格倾向（**判断类**，不可重抓） | run_date |
| `ml_eval` | 走前 ML 验证的样本外结论与门禁判定（**判断类**：面板会滚动，旧结论重算不出来） | run_date+ret_col+model |
| `fund_profile` | 场外基金档案 | code |
| `data_health` | 每次抓取的源/耗时/成功与否 | 自增 |

三条写进实现的纪律：

1. **幂等**。全部 `INSERT ... ON CONFLICT DO UPDATE`，同一天重跑、同一份数据重复落库
   都不产生重复行——这正是 `outcomes.csv` 曾经踩过的坑（盲目 append 让名义样本翻倍、
   t 值虚高）。
2. **失败不伪装**。写入返回**实际写入行数**，失败返回 0；数据层不可用时所有 API 退化成
   安全值（读 `None`、写 `0`），主流程继续走文件缓存，绝不把异常抛进业务链路。
3. **不替代原有产物**。`state/picks_*.json`、`outcomes.csv`、`positions.json` 照旧写，
   数据库是**新增**的结构化副本。

**什么该入库、什么继续留在文件缓存**——判据是「丢了能不能再拿回来」：

| 类别 | 例子 | 去处 | 理由 |
|---|---|---|---|
| 外部可重抓的原始数据 | 日线、榜单、财务指标、指数估值 | DB（结构化副本）+ 文件缓存 | 丢了大不了重抓，但入库后能 SQL 聚合、能看历史截面 |
| **判断/派生结果** | `macro_snapshot`（宏观分、建议仓位、风格倾向） | **DB** | 原始指标随时能再抓，「当时打了几分」抓不回来。不进库就只能靠逐个解析每日 `picks_*.json` |
| 计算过程产物 | `state/cache/phases/*`（回测/评估中间结果） | 文件缓存，**不入库** | 键是「行情内容指纹 + 参数签名」，语义是内容和地址绑定；搬进 DB 反而丢掉指纹含义 |

### 行情复用：什么时候可以直接用库里的数据

前复权 K 线以前**从不落盘**，每次运行为 60~70 只标的重新发请求。现在抓到的序列会入库，
下次四个条件同时成立才复用（见 `store.kline_is_fresh`）：

| 条件 | 为什么 |
|---|---|
| 距上次抓取 < `kline_ttl_hours`（默认 4h） | 跨日必须重抓，否则永远看不到新行情 |
| 该标的 `last_date` 不低于同市场最新日期 | 否则是落后的序列，复用会让面板截面宽度对不齐 |
| 库内行数 ≥ 本次请求的 `limit` | 300 根的历史顶不了 900 根的请求 |
| **没有跨越当日收盘时点** | 盘中 14:00 抓到的末根是未定盘的实时价；盘后若还命中，等于把盘中价当收盘价写进回测与复盘 |

最后一条最容易漏，也最危险：它不会报错，只会让数字悄悄错掉。

**行情失败时不会用陈旧数据顶替**——前复权 K 线直接驱动当日评分与买卖建议，拿几天前的
价格算 RSI/BOLL 会输出一个「看起来正常」的推荐。此时该标的本次缺席，并由报告开头的
数据完整性段落披露。反之 `raw` 不复权序列允许回退：它只喂估值分位这类长窗口统计，
陈旧几天对分位几乎无影响。

```bash
python run.py --db-stats      # 各表行数 / 行情覆盖 / 近 14 天数据源健康
QUANT_STORE=file python run.py   # 整体关闭数据层，完全走文件缓存
QUANT_DB=/tmp/x.db python run.py # 换一个库文件
```

## 短线轨：低吸 + 离场

### 1. 评分（六因子加权）

布林下轨贴近度、RSI 超卖甜点区(25~40)、缩量回踩、60 日线上方保护（防坠落刀）、MACD 柱拐点、近 20 日适度回撤。

### 2. 回测与预测力

- **回测**：候选近一年「低吸信号」——信号次日开盘买入，持有 5 日或触发止盈止损；输出胜率/场均/IR/Calmar/最大回撤。
- **截面 IC / Rank IC**：当日候选池里评分与回测场均收益的相关性，看「分数越高是否表现越好」。
- **滚动因子评估**（`factor_eval.py`）：把全部已拉 K 线摊成「市场×日期×标的」面板，逐日计算因子分与**前向收益**（次日开盘买、持有 N 日，与回测口径一致）的相关性，汇总为 **ICIR = IC均值/IC标准差**（信噪比）与 **Rank ICIR**。

> **实测诚实结论**：短线六因子全部 `|ICIR| < 0.1` 且无一显著，综合评分滚动 IC ≈ 0（±0.02 量级）。即**该评分体系在回测面板上预测力接近随机**。因此短线轨定位是**风控与纪律**，不是收益引擎——不要因其评分高就放大仓位。这个结论每日随报告自动复核。

### 3. 迭代（贝叶斯式权重更新）

每日复盘昨日推荐 → 滚动样本存 `state/outcomes.csv` → 满 20 笔后按「因子分与实际收益的滚动相关」微调权重：用相关性 **t 值调制学习率**（不显著则保守、显著则激进，显著负相关压到下限 0.05），版本化保存到 `params/`。

**调权闭环的四道完整性守卫**（每一条都对应一个曾真实发生、且会静默污染结论的缺陷）：

| 守卫 | 防的是什么 |
|---|---|
| 复盘**新鲜度**：行情最新交易日 ≤ 推荐日则跳过 | 推荐当天深夜/次日盘前复跑，取到的最新价仍是推荐日自己的收盘价 → 灌入一整批 `ret=0` 退化样本，把相关性和 t 值一起稀释向 0 |
| `outcomes` 按 `(date, code)` **幂等重写** | 盲目 append 把同一批样本记两次 → 名义 N 翻倍、t 值虚高（实测曾把 boll/rsi/drawdown 从「不显著」抬成 `t≈−7.7` 的「显著负相关」） |
| `iteration.last_used_date` **无新样本不调权** | 同日复跑让权重在没有新信息的情况下连续漂移 |
| 新权重**必须写回并落盘** | 曾长期存在：算完的权重从未赋回 `params["weights"]`，版本号照升而数字一动不动，整个调权闭环静默失效 |

`code` 一律按字符串读写（否则 `002026` 会退化成 `2026` 丢前导零，主键错位）。

**证据门禁**（回答「这点样本到底够不够支撑改权重」）：

| 门禁 | 规则 | 为什么 |
|---|---|---|
| 有效交易日 | 有效交易日 < `min_days`(20) 则**直接不调权** | 9 个交易日里各因子只有 9 个独立观测，任何相关性都不足以改权重 |
| 退化日剔除 | 某交易日全部 `ret` 恒为 0 → 整天剔除 | 这不是「0 收益观测」而是**缺失**（取到的是同一时点价格），留着会把相关性向 0 稀释 |
| DEFF 修正 | t 值用有效样本量 `n/DEFF` 计算 | 同日推荐同涨同跌，样本高度非独立 |

DEFF 由当日分组的单因素方差分析估出：`DEFF = 1 + (m̄−1)·ICC`，`ICC = σ²_between/(σ²_between+σ²_within)`。
**本项目实测 ICC≈0.36 → DEFF≈10.4 → 226 笔名义样本只等于约 18 笔独立观测，t 值虚高 3.2 倍。**

> 这条修正不是理论洁癖，它抓到过一次真实误判：某次自动运行按未修正的 t 值把 `rsi` 判为
> 「显著负相关 t=−3.82」并压到权重下限 0.05；按交易日分组后 `rsi` 的 IC=**+0.017**、t=**+0.11**，
> 即纯噪声。该次更新已回滚（`params/params_20260922_revert.json` 留有完整痕迹与回滚理由），
> 并加上上述三道门禁，防止同类误判再次发生。

报告第二章会自动披露**证据口径**（交易日数 / 名义笔数 / 有效样本量 / ICC / DEFF），
所以「够不够样本」不再是隐性假设，而是写在纸面上的数字。

### 4. 离场与持仓账本（卖出侧）

买入侧答「明天买什么」，离场侧答「明天卖什么」，共用同一份 K 线缓存。

**持仓账本**（`portfolio.py`）：每日推荐按评分降序登记为虚拟持仓（每市场上限 `config.exit_model.max_new_positions_per_market`），逐日结算，触发止损/止盈/到期即平仓并写入 `state/trades.csv`。持有天数按**交易日历**计（取 K 线日期集合），避免周末/假期误差。首次运行自动从最近一份历史推荐回填。

**离场模型**（`exit_model.py`）：把持仓路径抽象为离散马尔可夫状态
`S = (持有天数 d, 累计收益桶 r, 买入评分桶 s)`，值函数 `E(S) = E[继续持有到期的收益 | S]`。决策是**幅度 × 可信度**二维：

| 条件 | 动作 |
|---|---|
| `E ≥ τ*` | 🟢 继续持有 |
| `E < τ*` 且 `t ≤ t_min*` | 🔴 建议卖出 |
| `E < τ*` 但可信度不足 | 🟡 观察盯盘 / 收紧止损 |

`τ*` 与 `t_min*` 都**不写死**，在 `TAU_GRID × T_MIN_GRID` 上样本内联合扫描、样本外验证。加 t 门槛是必须的——`E` 在 ±0.05% 量级的偏差全是噪声，只按 `E<τ` 判卖会出现「浮盈 +1.8% 也清仓」的荒谬结论。桶内样本稀疏处向 `(d,r)` 与全局均值做两层贝叶斯收缩。

> **诚实边界**：远期实测中「期望驱动的提前离场」在样本外对平均收益是**中性偏风控**（改善尾部 5% 分位与胜率，不保证增收）。报告每日自动复核，若某日模型在样本外一次都没触发，会直接写明「与基线等价、无增量信息」。

**规则体检**：同一批信号下横向比较止损线/止盈线/持有期的历史表现。实测发现过紧的止损会把标的割在反弹前（符合「低吸依赖均值回归」的直觉），过早止盈会截断右尾。

### 5. 模型选型（walk-forward）

`model_select.py::select_short` 在 `hold_days × stop_loss × take_profit` 网格上做**样本内选参 → 样本外验证**的 walk-forward，只有当样本外增益不衰减到无意义时才建议切换参数；否则结论是「维持默认」。**选型层与调权层分开**：调权改的是因子权重，选型改的是离场规则与模型，两者都留痕。

选型层另有两条纪律，都是为了不把「换了风险偏好」误报成「策略更优」：

| 纪律 | 为什么 |
|---|---|
| 决策量用**日均收益**（`avg_per_day`，按每笔**实际持有交易日数**折算），不用原始平均收益 | 网格里持有期不同（3/5/8 日）。持有 8 日的组合天然比持有 5 日的多吃 3 天市场漂移，原始均值必然更高。实测样本演示：持有 8 日原始均值 **+3.03%** vs 持有 5 日 **+1.92%**（看着好 58%），折算成日均反而是 **+0.379%** vs **+0.385%**（略差） |
| **尾部守卫**：建议参数的 5% 分位比当前配置差超过 `TAIL_TOL = 2pct` 就不允许切换 | 低吸策略的核心风险在左尾（接飞刀）。靠加深尾部换日均收益不是改进，是换了风险偏好 |

> 今天这条守卫就拦下了一次：网格选出的「持有 8 日 / 不止损 / 不止盈」日均收益更高、样本外也未反向，
> 但 5% 分位从 −7.21% 恶化到 −10.52% → 结论为**维持当前配置**。
> 没有这条守卫，报告会给出一个「看起来样本外也支持」的切换建议。

## 长期轨：宏观 + 公司质量 + 估值

### 1. 宏观环境（`macro.py`）

五维打分：**PMI、CPI、M1-M2 剪刀差、利率、风险偏好**。每维有独立降级路径（单源失败即标 `missing` 且不参与总分）。输出：

- 综合分 `score` + 标签（如「中性偏暖」）
- 建议权益仓位区间 `equity_stance`
- 风格偏向 `style_bias`（大盘/小盘、价值/成长）

利率维度用**波动率归一化 z-score**，而非固定阈值——近 20 日国债 ETF 的绝对变动太小，固定阈值会永远卡在 50 分。

### 2. 标的池（分层抽样）

从成交额榜按三桶抽样：**龙头（leaders）/ 低估（cheap）/ 合理（fair）**，控制分析数量与请求量。剔除流通市值过小者。

### 3. 六维价值评分（`value_strategy.py`）

| 维度 | 关键指标 | 取值方式 |
|---|---|---|
| 质量 quality | ROE、毛利率、净利率 | 分段线性 `_band` |
| 成长 growth | 营收/利润同比 | 分段线性 |
| 现金流 cashflow | 经营现金流/净利润 | 分段线性 |
| 资产负债 balance | 有息负债、流动比率 | 分段线性 |
| 估值 valuation | PE、PB 历史分位、股息率 | **PB 分位用不复权价**，避免前复权篡改历史 |
| 宏观适配 macro | 与当前宏观风格/仓位的契合 | `macro_fit_bonus` |

> **金融股中性化**：银行/保险的毛利率、杠杆天然不可与制造业同口径，其现金流与资产负债维度强制置中性 60 分并加注，避免被机械扣分。

### 4. 基金与 ETF

- **场外基金**（`score_fund`）：业绩（夏普/最大回撤/近1年）、稳定性、规模趋势、经理任期四因子。
- **ETF 配置载体**（`build_etf_universe`）：无财报数据，**不参与价值评分**，按主题分组抽样，只给分类与近 20/60 日动量，作为宏观风格的落地工具。

### 5. 跟踪与前向验证（`value_track.py`）

- 每日推荐落盘 `state/longterm_picks_*.json`。
- `settle_tracking` 按 **5/20/60/120/250 交易日**里程碑结算每批推荐的实际收益，并与基准（**沪深300ETF 510300**）比较，输出**超额收益**——长期轨的成败看的是超额，不是绝对涨跌。
- `historical_replay`：**无前视**历史回放。财报用公告日 `NOTICE_DATE` 对齐（不是报告期末），估值分位取当期已发生的不复权价，逐时点重算六维分与前向收益。

> **实测证据**（长期轨首个显著信号）：回放面板 60 日 IC = **+0.115**（t=2.49）；120 日 IC = **+0.155**（t=5.24，正比例 89%）。即长期六维评分对 **2~4 个月**尺度收益有统计显著的预测力。这是全项目第一个显著信号（短线轨为近零），也是把长期轨独立出来的直接依据。

### 6. 长期模型选型

`select_long` 在同一回放面板上对比多套权重方案（`default / quality_first / valuation_first / equal`）。实测各方案 IC 均为正、方案间极差仅约 0.05 → **预测力来自信号本身而非权重调参**，结论是「维持默认权重、不切换」。

## 走前 ML 验证（`ml_eval.py`，`--ml-eval`）

用 scikit-learn 在长期轨的六维评分上做一次**样本外**验证：模型值不值得替代（或补充）现有规则分。

**它是验证器，不是预测器。** 新信号要谈「更好」，必须用**同一把尺子**——`value_track.cross_section_ic` 的按交易日分组截面秩相关。所以 ML 的样本外预测被当成一个「候选因子」丢回同一套评估里，与规则分 `score` 同台比较。评估原语 `_rank_corr` 也是直接复用，不另写一份。

**expanding window + purge，缺一不可。**

- *expanding window*：预测 t 时只用 `date < t` 的样本拟合，同一天的横截面不参与当日训练（同一天共享市场 beta，放进去等于送分）。随机切分的 CV 在时序数据上必然泄漏。
- *purge*：只按信号日切分**还不够**。前向收益是重叠窗口——实测截面间隔中位 22 天、持有 120 交易日（≈174 日历日），相邻截面的收益窗口重叠约 87%。把 t−1 的 (特征, 收益) 放进训练集去预测 t，等于提前看过同一段行情。所以训练样本必须满足「收益窗口已在测试截面之前完全结束」：`date(train) + horizon(日历日) + embargo ≤ date(test)`。

**这一步是真缺陷，不是保守起见。** 第一版没做 purge，GBR 报出样本外 IC=+0.49（t=11.4）；加上 purge 后塌到 **+0.039（t=0.38）**：

| 候选 | 未 purge | purge 后 | 样本外截面 |
|---|---|---|---|
| ML·GBR | +0.4906（t=11.44） | **+0.0393（t=0.38）** | 10 |
| ML·Ridge | +0.3340 | **−0.0132** | 10 |
| 规则分（基准） | +0.1546（t=5.24，全样本口径） | — | — |

**置换检验**：在每个截面内打乱收益、重跑整条流程 20 次，得到原假设下的 IC 分布 —— `−0.030 ± 0.068`（最大 +0.078），真实 +0.039 → **p=0.19，不显著**。它同时是整条流程的泄漏自检：若流程本身泄漏，打乱后的 IC 也会系统性偏离 0。

**四关门禁**（全过才建议接入）：样本外 IC 更高 + ICIR 不降 + 去 |IC| 最大 10% 的截面后优势仍在 + 置换检验显著（p ≤ 0.10）。外加样本底线：样本外截面 < 8 只报数、不下结论。

**当前结论：不过门禁 → 维持现状，ML 分数不接入评分。** 注意这个对比其实**偏向 ML**——规则分那 0.1546 是含重叠窗口的全样本口径（偏乐观），ML 是 purge 后的真样本外，ML 仍然输。

> 为什么不直接接进去：长期轨的 120 日 IC=+0.155(t=5.24) 是在「规则分」这一输入下验证出来的。往评分里塞 ML 分数会让已成立的结论失效、收益无法归因。要接入必须先过一次独立样本外复现。

结论写入 `reports/ml_eval_YYYY-MM-DD.md` 与 `ml_eval` 表（判断类数据：面板会滚动，旧结论重算不出来），日报里只显示一行摘要。
