# 虚拟试验版本衔接实施计划

2026-10-27，用户已授权实现、验证并恢复既有虚拟试验，同时寻找明确前复权的512880行情。

## 不变量及实现选择

- 使用SQLite只读快照复制到全新目标账本；原始账本、登记、启动请求和历史记录完整保留。目标中的账户、本金、持仓、订单、费用、资金流及已封存日终逐行保持，不重新开户或注资。
- 新副本追加不可变运行版本记录，绑定实验、原manifest散列、前一版本、生效日期、登记时刻、源快照、双账户检查点、代码及Python指纹和原因。策略、数量、风险、成本和来源不在衔接入口中开放修改。
- 衔接先核对日历连续性；拒绝倒填生效、覆盖已结算日期、跳过未结算日、双账户不一致或尚未纳入日终的事件。原账本版本不支持时继续走既有副本迁移入口。
- 新版本运行仍核对指纹；只允许在生效日期之后产生新日终，已封存日期只能按原意图回读。后续未登记代码变化仍暂停。
- 先在临时账本验证；目标完成审计后独占发布，失败不产生可用半成品。原始请求保留，新活动请求和活动指针明确指向新副本。
- 前复权源必须有明确口径和实际请求证据。raw数据、未知口径或缺真实因子均不得补造成qfq；新源复用已有存储和准入检查。

## 实施与验证顺序

1. 实现`paper_runtime.py`、试验运行版本解析及显式CLI，回归复制保真、链式衔接、幂等、冲突、日期边界、双账户恢复和故障回滚。
2. 独立排查512880的公开前复权接口；若可用，补适配器与拒收口径错误的回归，并在隔离库联网验证。
3. 待源码稳定后运行全量pytest、必要离线自检、构造集成与相关静态检查；独立复核版本衔接边界。
4. 对真实原账本取只读指纹，在新副本执行衔接并核对完整历史与现金；发布新活动请求，验证运行版本就绪。实际日终仍等待北京时间16:00，禁止伪造时钟。
5. 可用的前复权源经验证后刷新完整窗口、冻结新快照；记录真实采集结果与其余限制，更新冷启动说明和本轮交付记录。

本轮主流程使用`brainstorming`、`writing-plans`、TDD、完成前核验；外部源使用有证据排障及HTTP弹性规则。个人本地SQLite不走公司DBPaaS。当前工作区已有用户改动全部保留，不进行Git交付。
