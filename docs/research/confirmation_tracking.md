# 确认信号逐日跟踪与优先级变化

## 范围与实施顺序

1. 新增 `research_tracking.py`：固定观察规则、逐日核验、前一交易日排名比较、SQLite台账。
2. `daily_research.py` 在原有研究事务内登记/核对，并将结果随run_id归档；重复输入只读既有结果。
3. 主报告显示四项状态、证据日期/数值与排名变化；明细保留完整规则、来源和历史。
4. 离线测试覆盖确认/回落/低点破坏/缺失/修订、跨日排名、重复执行与失败回滚；实际运行日报。

## 固定语义

- 仅从真实发布的研究优先清单建立观察，不按历史行情回算虚构旧日推荐。
- 同一轮入选期间固定原观察日高/低点、参数、历史输入、登记时刻；连续入选不每天重置。
  退出清单后结束该轮观察；以后重新入选才建立新轮次，旧轮次保留。
- 只检查原观察日之后、且登记时已不可见的完整日线：盘前/盘中登记可从当日收盘起核对；
  盘后登记不追认当日已经可见的收盘。登记日与行情交易日分开保存。
- 四项分别核验：收盘突破原高点；MACD柱>0；收盘>动态MA60；回踩日
  （收盘<=前收）量比处于[0.4,0.9]。量比窗口沿用登记时参数。
  非回踩日不误判量能失效，保留最近适用日的结果并注明。
- 待确认：未曾满足；已满足：最近适用日满足；已失效：曾满足后不再满足。
  单项条件回落后允许再次满足，但保留首次满足日期与逐日核验记录。
  任一后续日线最低价<原观察低点使整轮观察终止为失效，不自动复活；保留首次满足/失效日。
- 另有“暂不可判定”：缺行情、未推进、历史输入修订、历史覆盖不足等；不假报满足/失效。
  已知低点破坏的终止记录不会因缺数据而被抹去。
- 日内重跑与输入/代码修订不增加交易日证据。来源历史发生修订时不直接比较旧qfq阈值。
- 排名按相同观察池、股票/ETF各自前3与原有62分阈值；比较行情序列中严格前一交易日
  的留档，缺该日记录则不跨越缺口冒充“较昨日”。给出新增/退出/上升/下降/持平和得分差。
  数据缺失不伪装成退出；参数口径变化单独提示。
- 此层仅跟踪技术研究条件，不修改生产评分、不做自动买入、不算策略准入验证通过。

## 持久化与恢复

在现有 `ledger.db` 新增会话、观察轮次、核验三张表。自然唯一键和原有
`BEGIN IMMEDIATE` 保证单写者/重复执行安全；所有写入与研究记录同一事务提交或回滚。
历史输入与规则留在观察轮次，核验结果按观察id、行情日、run_id追加，原研究run不回写。
同日记录允许不同输入版本，比较时取前一交易日最后一次实际留档。
