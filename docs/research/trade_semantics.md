# 信号成交与收益标签契约

任务2，2026-10-26。语义真理源为 [trade_semantics.py](../../src/quant_agent/domain/trading/labels.py)。
新合约版本为 `next_open_close_v1`；本步只统一未扣费的日线价格模拟，不代表真实成交或完整组合绩效。
后续验收以[给定本金的虚拟投资账户](paper_account_validation.md)为主线：日线标签是基础，
不以真实账户成交作为验证前提；账户现金、数量、费用和每日净值由后续任务3–7补齐。

## 时点与收益

信号日收盘后冻结评分与离场规则，先登记待入场；取得下一根完整日线后，使用该日线的开盘价作为模拟入场价。
入场日计持有第1日。持有期为5时，信号后第5根日线的收盘为到期终点，不按5个日历日计算。
止损／止盈只在日线收盘判断，触发则用该收盘价结束；未到期且未触发时，不生成已实现收益标签。
标签未成熟只限制训练／统计证据；虚拟账户仍须逐日计入未平仓浮盈亏并更新净资产。
缺少完整到期窗口时，回测不再强行以最后一根行情当作到期平仓。

| 字段 | 定义 |
|---|---|
| `signal_date`、`signal_time` | 评分信号的行情日期及 `YYYY-MM-DD@close` |
| `entry_date`、`entry_time` | 后续第一根完整日线日期及 `YYYY-MM-DD@open`；尚未取得时为空 |
| `reference_price` | 观察时的参考价格；不充当成交价 |
| `entry_price` | 下一根日线开盘价，必须为有限正数 |
| `label_end_date`、`label_end_time` | 实际达到终点的日期及 `YYYY-MM-DD@close`，提前止盈止损时保留真实提前日期 |
| `exit_price`、`ret` | 终点收盘价及 `exit_price / entry_price - 1`，不扣费；未成熟标签的`ret`为空 |
| `label_spec` | 冻结的 `hold_days`、`stop_loss`、`take_profit`；后续参数变化不改原信号规则 |
| `label_version`、`label_id` | 语义版本与上述规则的确定性指纹；规则不同的收益样本不混用 |

`@open`、`@close` 是交易阶段标识，不是伪造的时区时间戳；本步没有填入各交易所具体开收盘时间。
主入口对A股／ETF复用现有北京时间16:00完整日线截止规则，避免以盘中当日收盘价结算。
运行采集日和日线信号截止日分开记录，避免把盘中资金流／宏观快照回写到上一日。
已有当日日线但尚未完成时，只可复用此前冻结的旧信号，不用盘中候选池补造上一日首次信号。
本步支持新信号的市场为`cn`、`etf`；海外交易时段和场外基金净值尚未接入此合约，保留原观察入口。

## 固定标签与策略标签

[factor_eval.py](../../src/quant_agent/domain/research/factors.py) 的 `forward_return` 和默认 `build_panel` 继续计算不含止盈止损的固定持有期标签。
`build_panel(..., label_spec=params["backtest"])` 显式请求策略标签，与
[backtest.py](../../src/quant_agent/application/research/backtest.py)、[evaluate.py](../../src/quant_agent/application/investing/evaluation.py)、[portfolio.py](../../src/quant_agent/application/investing/portfolio.py)
使用同一解析器。面板增加实际入场日期、标签终点、版本及指纹，为后续日期切分提供依据。
不能把固定持有期IC和含提前离场的收益说成同一实验。

构造案例：信号日参考价100，下一根日线开盘110，第5根后续日线收盘121。
四条路径的策略价格收益都是10%，不再分别使用100或最新报价作分母／分子。
若第2根后续日线收盘99并触发-5%止损，策略标签为-10%，而固定持有期标签仍为10%。
此差异来自明确的退出规则；日线止损并不保证恰好按-5%成交。

## 事前留档与漏跑

- `state/picks_v2_YYYY-MM-DD.json` 冻结当日第一轮信号及标签规则；同日重跑复用首份留档，不重置未来待验证条件。
- 主入口将这份冻结信号传给待入场账本。`pending`不作为已持仓传入离场模型；取得开盘和后续完整日线后才进入`open`／`closed`状态。
- 复盘遍历全部此前的v2留档，用各自原始日期和规则补结算成熟标签；不只查看最新一份，也不使用当前报价替代漏跑期间的终点。
- 复盘结果写`outcomes_v2.csv`，按信号日、市场、代码、标签指纹幂等登记；成熟结果首次记录后不因重复运行或历史修订而重写。
- 新平仓写`trades_v2.csv`，账本记录状态后重复结算不再次追加；两者均保留标签终点。完整资金账本、故障原子性与账户对账属于后续任务5–7。
- 调权只读取与当前标签指纹一致的v2样本；原有交易日数、退化日、DEFF与幂等门禁继续存在。完整日期窗口和候选晋级仍在任务9。

同日现算的观察列表可以随输入变化；已冻结的待验证信号不因此被替换。
策略改动、数据版本、测试封存和搜索预算的完整实验身份将在任务9登记，标签指纹不替代实验身份。

## 缺失与旧记录

没有日线、缺信号日、开盘价／路径收盘价非有限正数，均不生成成熟标签。
已提供市场日期序列时，发现缺少预期的入场日、持有路径或已应出现的终点，标为暂不可判定，不能把后来的价格顺延作原成交。
没有独立日期序列时，仅能按观察到的标的日线计数；本步不声称已经补齐停牌、历史成分或官方交易日历。
主入口的日期序列来自现有行情并集／基准，真实性与完整性仍需任务3核验。

新账本记录已观察的入场价及收盘路径；后续发现对应历史修订时，保留旧值并标记`revised_history`，
暂不生成新平仓或模型建议。缺行情同样保留状态，不能静默清空持仓。
已成熟复盘记录保持原留档值，这不等于拥有历史当时可见的完整价格数据库。

旧`picks_YYYY-MM-DD.json`、`outcomes.csv`和`trades.csv`保留原样，不转换为新标签或新训练样本。
旧账本持仓保留状态及原价格，标为`legacy_unverified`；原参考价下的风险触发单列为人工复核信息，
不伪造成新口径成交，不与v2收益统计混合。首次回填只接受有明确版本的v2留档，并保持幂等。
本步没有对已有本地账本执行迁移或新一轮跑盘。

## 验证入口与范围

```bash
.venv/bin/python -m pytest -q tests/test_trade_semantics.py tests/test_indicator_backtest_boundaries.py tests/test_local_research.py tests/test_research_tracking.py
.venv/bin/python tests/offline_e2e.py --synthetic
```

`--synthetic`只生成固定种子的构造行情，在独立临时目录执行集成测试，不读真实推荐、不联网。
默认`offline_e2e.py`及`verify_phase_cache.py`仍依赖行情缓存，不能把新例外入口的结果当成真实行情验收。
测试覆盖正常到期／提前止损、周末与长间隔、漏跑、未成熟／缺失、同日冻结、重复结算、跨市场同代码、
固定／策略标签区分、历史修订、旧持仓风险呈现以及调权门禁。

费用／滑点／成交限制、逐日现金与净值、分红／拆股、真实历史时点、无泄漏选型和独立前瞻收益仍待对应任务验证。
本步不证明投资策略有效，也不把回测中的日线开盘／收盘价当作已成交的现实证据。
