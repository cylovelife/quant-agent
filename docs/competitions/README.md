## 正式比赛的选择门槛

赛题发布后先用一页选题卡作决定。以下条件必须真实成立：

1. 官方仍开放，报名、组队和提交截止时间明确，我们能实际满足资格与规则。
2. 任务是预测、排序、时序决策或可迁移的数据分析问题；首选日频金融，不因题名带 banking 就接。
3. 数据能合法获取，标签/推断协议明确，能建立与测试分布相称的验证；隐藏或未来评估优先。
4. 小样本可在现有资源运行，完整训练、推断与代码提交预算经过实测；赛程留有至少一个完整迭代周期。
5. 我们能写出具体竞争假设：特征时点、结构、状态适应或推断效率中至少有一个可测突破口。

对通过条件的候选，比较主题迁移、评测质量、迭代速度、资源负担和团队差异化，不用没有测量基础的加权总分伪装精确。若 2028 Cup 只提供不相关赛道，仍以 Cup 前三为结果目标，但须重新评估领域学习、算力与真实队友需求；不假定它一定有金融题。

选中正式主赛后，停止无关热身与大范围追新模型。以本地验证组织搜索，Public LB 用于校准任务理解和模型是否失配，避免把平台反馈当调参训练集。

## 技术主线：先形成优势，再增加复杂度

第一层是可信比较：训练集独立拟合预处理、按真实标签结束日 purge、未来数据扰动测试、相同输入和预算、记录全部尝试。第二层是强基线：多数类/常数、Logistic 或 Ridge、CPU 树模型；具体模型随分类或回归任务适配。第三层才是状态适应、特征交互、稳健融合与任务适配神经网络。

首个可证伪研究假设：**在相同特征和搜索预算下，按市场状态做轻量校准，能否比固定模型和滚动重训更稳健？** 先比较固定模型、滚动窗口、指数衰减、简单因果状态校准，只有新增窗口上的增量足以覆盖复杂度，才实现 ReCAP 式机制。状态判别只能读取当时数据，不能用全样本平滑后的状态标签。

当前先把这个主张作为待检验方向，不称为创新或前三秘诀。金融序列的有效样本少，多个随机种子不等于多个独立市场阶段。最终融合用训练外预测拟合，验证各分量是否互补，按官方指标选择权重，并遵守赛题对在线更新和延迟标签的限制。

## 协作、投入与调整

用户已确认每周投入 **8–12 小时**，首阶段只使用本机和平台免费额度。每周安排四个1.5–2小时的主要工作时段、1小时复盘及1–3小时机动，共8–12小时；机动时间用于处理失败或补齐验证，不默认增加模型搜索。已测本机为 Apple M2、16 GiB 内存，工作卷约 104 GiB 可用；D3小型练习脚本内部耗时0.417秒，不含启动、准备与开发，不能外推Hull完整训练性能。免费额度不足时先缩样、缩模型或调整进度；付费算力仅列备选方案，实际启用前需另有明确预算授权。
