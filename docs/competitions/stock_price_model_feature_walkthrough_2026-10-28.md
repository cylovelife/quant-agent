# Kaggle 股价预测代码讲解：从马尔可夫链到特征监督学习

日期：2026-10-28。对应比赛：Stock Price Predictor。适合已经接触过马尔可夫链、希望理解本次数据处理、特征提取和模型训练的读者。

这部分代码的核心是：**把截至当天的价格历史压缩成一行特征，再用这一行预测下一条记录是否上涨。** 时间依赖通过滞后收益、滚动统计和日历信息进入模型；模型不必直接接收完整序列，也可以进行时间序列预测。

先区分本次实现与最终提交的关系：

| 部分 | 作用 | 是否用于最终提交 |
|---|---|---|
| 星期条件概率模型 | 统计每个星期几之后的上涨比例 | 是，输出方向另有公开榜反馈后的互补处理 |
| 18项特征 + Logistic / 浅层提升树 | 检验价格信息能否提供额外预测力 | 否，对照实验 |
| 事件时钟特征 | 减少重复价格对窗口统计的干扰 | 否，对照实验 |
| AR(5) / ARX(5) + Ridge | 显式利用收益率的自回归关系 | 否，对照实验 |

这些方法不是串联在一起的大模型。完整代码目录见 [CODE_MAP](CODE_MAP.md)，实验与提交来源见[当天复盘](rank2_2026-10-28.md)。

## 1. 一条样本预测什么

原始价格列为 `Date, Open, High, Low, Close`，训练文件另有 `Target`。数据没有股票代码或交易所字段，因此这里只能确认是一条身份未知的 OHLC 序列，不能当作多股票面板。

记当天开、高、低、收分别为 $O_t,H_t,L_t,C_t$，标签为：

$$
y_t=\mathbf{1}(C_{t+1}>C_t)
$$

下一条记录收盘更高为1，更低或相等为0。**这里的 $t+1$ 是下一条自然日记录，不是下一交易日。** 原文件包含周末重复价格，必须按提供的标签定义理解预测任务。

预测发生在当天收盘后：

```text
已经知道：今天及以前的日期、开盘价、最高价、最低价、收盘价
需要预测：下一条记录的收盘价是否高于今天
```

因此，今天的收盘价和最高价可以作为输入。如果任务改为“今天开盘前预测今天涨跌”，这些输入就会越过预测时点。

代码入口：[data.py / load_dataset](../../src/quant_agent/competitions/stock_price/data.py)。

## 2. 与马尔可夫链的联系

假设以前把市场离散为“上涨、下跌、横盘”，用 $S_t$ 表示当前状态，一阶马尔可夫链通常假设：

$$
P(S_{t+1}\mid S_t,S_{t-1},\ldots)=P(S_{t+1}\mid S_t)
$$

随后通过转移计数估计条件概率，例如“今天上涨之后，明天上涨的概率”。

本次特征模型换了一种表示历史的方式：

$$
x_t=\phi(\text{截至 }t\text{ 的历史}),\qquad
P(y_t=1\mid x_t)=f_\theta(x_t)
$$

- $\phi$ 是特征提取代码，把价格历史概括为收益、波动、K线位置、星期等数字。
- $x_t$ 是当天的多维状态描述。
- $f_\theta$ 是通过训练得到的预测函数。

| 环节 | 离散马尔可夫链 | 本次特征监督模型 |
|---|---|---|
| 描述当前情况 | 一个离散状态 | 一个多维特征向量 |
| 利用历史 | 通过当前状态，或增加阶数 | 通过滞后收益、滚动统计等输入 |
| 学习规律 | 统计状态转移次数 | 优化分类或回归损失 |
| 输出 | 下一状态的概率分布 | 上涨概率，或下一期收益估计 |

可以把特征理解为一种“历史摘要”，但代码没有证明它是充分状态，也没有证明它满足马尔可夫性。当前模型直接学习摘要与下一期结果的关系，没有估计完整的状态转移过程。

Logistic 本身不维护序列记忆；它仍能用于时序预测，是因为每行输入已经包含过去窗口的信息。

## 3. 数据处理：先保证每一行的含义可信

### 3.1 文件、日期和价格校验

`load_dataset()` 先检查文件 SHA-256、工作表、列名和行数，并核对两个目录中的重复文件。六个原文件实际是三对副本，不能合并为两倍样本。

随后校验：

- 日期唯一、递增，且按自然日连续。
- 价格有限且大于零。
- `High` 不低于 `Open/Close/Low`，`Low` 不高于其他价格。
- 训练与测试日期连续且不重叠。

文件校验确认“读到的是哪份输入”，价格校验确认“这份输入是否符合当前任务约定”。哈希一致本身不能证明标签或金融语义正确。

### 3.2 标签校验与训练末行排除

训练标签的 Excel 公式比较下一行收盘价与当前行收盘价。前1459条标签均能与 TRAIN 内相邻收盘比较核对；最后一条公式引用空白行，缓存值0不代表可信答案，因此排除。

**排除的是最后一行的标签，价格仍保留。** 这条价格可以作为之后测试期的历史输入；没有可信标签不等于没有可用价格。

加载后分成三个对象：

```text
prices：训练与测试价格，供因果特征计算
labels：可信训练标签，以及每条标签实际结束日期 label_end
sample：提交 ID 顺序；其中 Target 是占位值
```

数据审计细节见[第2天记录](day2_stock_price_predictor.md)。

### 3.3 为什么可以拼接训练和测试价格

拼接后，测试第一天能使用训练末尾的历史窗口。是否泄露取决于特征的依赖方向：当天特征只能读取当天及以前的数据。

代码使用向后的 `shift()`、`pct_change()` 和包含当天的历史滚动窗口，没有用测试相邻价格生成测试标签，也没有用未来价格后向填补历史。

验证和推断模拟的是逐日观察后的一步预测。例如预测测试期第10天之后的结果，可以使用第10天已经观察到的价格。它不是在训练截止日一次性预测未来整年的价格路径。

## 4. 18项特征怎样提取

实现入口：[baseline.py / build_features](../../src/quant_agent/competitions/stock_price/baseline.py)。这些特征是事先固定的人工统计摘要，没有使用 PCA 或神经网络自动表征，也没有按全样本标签相关性筛选特征。

| 特征 | 数量 | 计算方式 | 描述什么 |
|---|---|---|---|
| `weekday_0` 至 `weekday_6` | 7 | 星期一至星期日的 one-hot | 日历结构 |
| `return_1/3/7/14` | 4 | $C_t/C_{t-k}-1$ | 不同窗口的累计涨跌 |
| `intraday` | 1 | $C_t/O_t-1$ | 当天开盘到收盘的方向与幅度 |
| `open_gap` | 1 | $O_t/C_{t-1}-1$ | 相对上一收盘的跳空 |
| `range` | 1 | $(H_t-L_t)/C_t$ | 当天振幅 |
| `close_position` | 1 | $(C_t-L_t)/(H_t-L_t)$ | 收盘在当天区间中的位置 |
| `volatility_7` | 1 | 最近7个单期收益的样本标准差 | 近期波动 |
| `distance_mean_14` | 1 | 收盘价 / 最近14条收盘均价 − 1 | 相对近期均价的偏离 |
| `repeated_ohlc` | 1 | OHLC 是否全部与上一行相同 | 是否出现重复行情 |

### 4.1 累计收益不等于收益的滞后值

下面两段是不同的表达式片段：

```python
close.pct_change(7, fill_method=None)
close.pct_change(fill_method=None).shift(7)
```

第一段是 $C_t/C_{t-7}-1$，回答过去7条记录累计涨了多少。第二段是先计算单期收益，再取7期前那一项，回答7期前那一天涨了多少。后面的 AR 模型使用第二类滞后结构。

### 4.2 各组特征提供互补的状态描述

`return_14 > 0` 表示近期整体上涨；`distance_mean_14` 较高表示当前明显高于近期均价；`volatility_7` 较高表示近期收益波动较大；`close_position` 接近1表示今天收盘接近当天最高价。

这些描述本身不等于交易结论。高位可能延续，也可能反转，需要由训练样本检验与标签的关系。

星期采用7维 one-hot，而不是直接把0至6当成连续数值。这样不会强迫线性模型认为星期几越大，上涨倾向就必须单调变化。

### 4.3 一个数值例子

以下数字仅用于演示公式，不是比赛样本：

```text
上一收盘：105
今天 Open=100, High=112, Low=98, Close=110
```

| 特征 | 结果 |
|---|---|
| `return_1` | 110 / 105 − 1 ≈ +4.76% |
| `intraday` | 110 / 100 − 1 = +10% |
| `open_gap` | 100 / 105 − 1 ≈ −4.76% |
| `range` | (112 − 98) / 110 ≈ 12.73% |
| `close_position` | (110 − 98) / (112 − 98) ≈ 0.857 |

这行数字描述了低开、盘中上涨、收盘靠近高点的组合，比单独一个“今天上涨”保留更多信息。比例表达减少了绝对价格尺度差异，但不保证序列已经平稳。

### 4.4 窗口、预热和缺失处理

`rolling(7)` 与 `rolling(14)` 都包含当天，因为预测发生在收盘后。7期波动使用 pandas 默认的样本标准差；14期均价包含 $t-13$ 至 $t$，而 `return_14` 还需要 $t-14$ 的价格。

因此最初14行无法算齐，调用方通过 `dropna()` 排除。可信标签1459条，减去14条预热，最终训练1445条。

当 `High == Low` 时，`close_position` 的分母为零，代码把位置设为中性值0.5。无穷值先转为缺失，再由调用方排除；没有拿未来数据补齐窗口。

## 5. 三个基线模型怎样学习

共同入口：[baseline.py / fit_predict](../../src/quant_agent/competitions/stock_price/baseline.py)。

### 5.1 星期模型只学习七个条件概率

核心代码片段为：

```python
rates = train.groupby(train.Date.dt.dayofweek).Target.mean().to_dict()
```

二元标签的均值就是上涨比例：

$$
\hat p_d=\frac{\text{训练集中星期 }d\text{ 的上涨次数}}{\text{训练集中星期 }d\text{ 的样本数}},\qquad
\hat y_t=\mathbf{1}(\hat p_{\operatorname{weekday}(t)}\ge0.5)
$$

未在训练中出现的星期回退到整体上涨比例。虽然共同数据流程生成了18项特征，这个模型预测时实际只读取 `Date` 中的星期。

它在本题表现强，与数据结构有关。周末重复价格意味着：

```text
周五 → 周六：收盘相等，周五的标签为0
周六 → 周日：收盘相等，周六的标签为0
周日 → 周一：才可能发生变化
```

作为示意，假设每周两天必然不涨，其余五天涨跌各半，那么识别这两天、其余随机猜测，期望 Accuracy 就约为 $(2+5\times0.5)/7=64.3\%$。这不是实际成绩的精确分解，但解释了日历信息为什么能形成强基线。

### 5.2 Logistic 学习上涨概率

流水线为：

```text
训练内中位数填补 → 标准化 → LogisticRegression
```

模型形式为：

$$
p_t=\sigma(b+w^\top z_t),\qquad \sigma(a)=\frac{1}{1+e^{-a}}
$$

$z_t$ 是标准化特征。模型通过带正则化的分类损失学习权重，把线性得分映射到上涨概率。`C=0.1` 表示相对较强的正则化；在 scikit-learn 中，C 越小，正则化越强。参见[对应版本线性模型文档](https://scikit-learn.org/1.7/modules/linear_model.html#logistic-regression)。

标准化使用训练窗参数：

$$
z_{t,j}=\frac{x_{t,j}-\mu_{\mathrm{train},j}}{\sigma_{\mathrm{train},j}}
$$

验证和测试沿用训练得到的均值、标准差，不能各自重新拟合。当前调用方已先 `dropna()`，因此中位数填补在这批正常输入中基本没有实际工作，预热行也不是靠它补出来的。

### 5.3 浅层提升树学习非线性条件组合

树模型能表达“近期收益为正时，低波动与高波动分别采用不同判断”之类的组合关系。这是模型能力示意，不是从本次实际树中提取的规则。

梯度提升逐轮增加小树以降低当前损失，分类时可以理解为不断修正上涨的得分。`Hist` 表示使用直方图分箱加速切分搜索。代码固定深度2、最多4个叶子、60轮、学习率0.05、每叶至少40行、L2正则化10，控制小样本过拟合。参见[对应版本分类器文档](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.HistGradientBoostingClassifier.html)。

内部早停关闭，评价依靠外部预设时间窗，避免把随机内部切分作为本题的时间验证。

## 6. AR 和 ARX 如何利用收益率历史

实现入口：[timeseries.py](../../src/quant_agent/competitions/stock_price/timeseries.py)。先定义单期收益 $r_t=C_t/C_{t-1}-1$，AR(5) 使用当前及前4期收益：

$$
x_t=[r_t,r_{t-1},r_{t-2},r_{t-3},r_{t-4}],\qquad
\hat r_{t+1}=b+\sum_{k=0}^{4}a_k r_{t-k}
$$

`return_lag_0` 是当天已经实现的收益，预测目标仍为下一期收益，没有时间错位。

代码采用 `StandardScaler + Ridge(alpha=10.0)`。对标准化后的输入，目标可写为平方误差加系数惩罚：

$$
\sum_t(r_{t+1}-\hat r_{t+1})^2+\lambda\sum_k a_k^2
$$

Ridge 约束系数，降低相关滞后输入造成的估计不稳定性。ARX 在收益滞后之外，增加星期、K线实体、上下影线、振幅和跳空：

$$
\hat r_{t+1}=b+\sum_{k=0}^{4}a_k r_{t-k}+\beta^\top u_t
$$

其中实体为 $(C-O)/O$，上影线为 $(H-\max(O,C))/O$，下影线为 $(\min(O,C)-L)/O$。这里的 X 指额外解释变量；变量仍由价格构造，不能据此断言具有因果外生性。自回归与额外解释变量的结构可对照 [statsmodels 官方说明](https://www.statsmodels.org/stable/examples/notebooks/generated/autoregressions.html)，本次实际拟合使用 sklearn Ridge。

### 6.1 收益回归与方向分类不是同一个目标

Logistic 直接估计上涨概率；AR 先预测收益大小，再用 `forecast > 0` 转成涨跌类别。

假设某状态下60%概率涨1%、40%概率跌3%，那么最可能的方向是上涨，期望收益却是 $0.6\times1\%-0.4\times3\%=-0.6\%$。所以收益回归更准，不必然带来更高分类 Accuracy。

### 6.2 实际实现还带星期零标签分支

每个训练窗内，某星期至少20条样本且训练标签全为0，就对该星期直接输出0，其余样本用于拟合收益模型。该规则只读取训练标签，不读取验证标签。

因此本次是带日历分支的 AR/ARX 对照，不能把所有预测都解释成单一线性自回归方程的结果。函数返回的 `forecast` 是回归预测值，最终 `prediction` 还会被星期分支覆盖，两者需要区分。

## 7. 事件时钟为什么改变特征窗口

实现入口：[event_clock.py](../../src/quant_agent/competitions/stock_price/event_clock.py)。考虑以下示意序列：

```text
周五：100
周六：100
周日：100
周一：102
```

自然日时钟会记录两个零收益，事件时钟只在 OHLC 发生变化时新增观察。`event_features()` 按以下步骤计算：

1. 找出 OHLC 相对上一行发生变化的记录。
2. 在变化记录上计算1/3/5/10期累计收益，以及5/20期波动和均价偏离等特征。
3. 将最近已知事件特征向前填充回每天。
4. 增加距最近变化的自然日数 `days_since_change`，并保留当天星期信息。

这里的向前填充只传递已经发生的事件，不会把周一的新价格填回周末。**改变的是特征的计时方式，官方样本、提交行和下一自然日标签不变。** 由于标的与交易所未知，也不能把所有 OHLC 不变的记录直接认定为休市日。

## 8. 时间切分与标签成熟边界

实现入口：[validation.py / purged_window](../../src/quant_agent/competitions/stock_price/validation.py)。训练样本必须同时满足：

```python
(Date < start) & (label_end < start)
```

例如验证从1月1日开始，12月31日的特征虽然属于过去，但它的标签依赖1月1日收盘，尚未在边界前成熟，因此也要剔除。这就是此处的 purge：清除标签跨越时间边界的样本。

验证样本则要求 `start <= Date < end`，并且 `label_end < end`。代码使用下一条实际提供记录的日期，不猜测交易所日历。

三个基线使用2017年上半年、2018年上半年两个开发窗，分别用各窗口之前的成熟标签训练；选型锁定后，再评价一次2019年保留窗。模型参数在每个评价窗内固定，但每日特征可使用截至当天新观察到的价格。这是固定参数的一步预测评价，不是窗口内每日重训。

随机打散会让未来样本进入历史训练，并可能夸大成绩。滞后特征配合时间评价的例子见 [scikit-learn 官方教程](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html)；训练内拟合预处理的边界见[数据泄露说明](https://scikit-learn.org/1.7/common_pitfalls.html)。

## 9. 本次结果应该怎样理解

### 9.1 为什么最终保留星期模型

两个开发窗的记录如下，来源为[第3天记录](day3_stock_price_predictor.md)：

| 模型 | 开发窗1 | 开发窗2 | 平均 Accuracy |
|---|---|---|---|
| 训练多数类参考 | 62.78% | 60.56% | 61.67% |
| 星期模型 | 62.78% | 66.11% | 64.44% |
| Logistic | 60.56% | 67.78% | 64.17% |
| 浅层提升树 | 63.33% | 65.56% | 64.44% |

`choose_model()` 按从简到繁的顺序比较，复杂模型须同时满足：平均 Accuracy 至少增加1个百分点；其最差窗口 Accuracy 不低于当前所选模型最差窗口超过1个百分点。这里比较的是两组分数各自的最小值，不是逐个对应窗口分别约束。

两种复杂模型没有提供足够增益，因此保留星期模型。锁定后2019年保留窗为215/324，Accuracy约66.36%，多数类参考约59.26%。这支持当前设置下的模型选择，不证明复杂模型在其他数据上无用，也不代表真实投资收益。

后补 AR/ARX 使用2019年之前的四个开发窗；同一研究中，星期参考、AR、ARX 的平均 Accuracy 分别为64.87%、66.95%、66.40%，但2018年下半年 AR/ARX 分别比参考退化约5.46和3.83个百分点，未通过采用门槛。该研究的门槛是逐个对应窗口检查退化，与前三个基线比较最小值的实现需要区分。

AR研究与原基线研究的窗口、预热和有效样本不同，不能把两张表的平均分直接当成同条件比较。详见[AR/ARX复盘](rank2_2026-10-28.md)。

### 9.2 最终线上分数还包含提交层处理

原样例只有364条输入，而服务器要求大写 `ID` 和365条预测。提交层保持原364条顺序，对没有价格输入的 ID 364 使用训练多数类先验0，不虚构日期或 OHLC。

先提交原始方向，官方分数约32.054%；随后依据公开榜反馈，对全部365条输出执行 `1-y`，得到约67.945%。因此最终提交由星期模型、缺失输入先验及公开榜自适应方向选择共同构成，不能把线上高分归因于 AR/ARX，也不能当作独立验证出的泛化能力或官方标签反向的证明。

该处理位于 [submission.py / server_rows](../../src/quant_agent/competitions/stock_price/submission.py)，模型重拟合与文件复现位于 [reproduce.py](../../src/quant_agent/competitions/stock_price/reproduce.py)。线上分数为2026-10-28的历史记录，完整回执见[当天复盘](rank2_2026-10-28.md)。
