# quant-agent 自循环（RSI）系统设计方案 v1

> RSI = Recursive Self-Improvement（递归自我改进）：系统每天拿次日真实数据校验自己的预测，
> 修正因子与模型参数，再预测下一天——循环往复，直到收敛到一组**经得起样本外检验**的参数。
>
> 本方案是设计文档，不是实现。按「先设计、后编码、逐阶段验收」推进。
>
> **状态标记**：✅ 已核实（本仓库源码/报告/外部一手来源）；⚠️ 待核验；❌ 已证伪。
> **Phase 0 核验已完成（2026-09-25）**，核验台账见 `docs/research/phase0_verification.md`。
> **Phase 1 数据通道探针已完成（2026-09-29）**，实测台账见
> `docs/research/phase1_data_channel_probe.md`；本文档已升级至 v1.2，
> 吸收了 Phase 0 核验结果与 Phase 1 探针的三项修正（资金流口径 / 第二源选型 / adapter 纪律）。

### 0.2 必须直面的事实（设计的第一性约束）

已验证的三个结论，决定了这个循环系统的设计走向：

1. **短线逐日价格方向预测，当前没有任何显著信号**（六因子全灭，样本外 −0.220pct）。
2. **唯一显著的信号在慢频**：长期轨 120 日截面 IC +0.155。
3. **循环系统最贵的学费都付在自欺上**：重叠窗口泄漏让 GBR 的 OOF IC 从 +0.039 虚报到
   +0.4906（t=11.44），加 purge+embargo 后塌回真实水平。

**推论**：这个自循环系统的核心风险不是「迭代不动」，而是「循环把噪声迭代成幻觉」。
因此本方案把**验证门禁作为架构的一等公民**，而不是事后补丁。

## 1. 目标定义：什么叫「高水准」

把「实现高水准的股票价格预测」翻译成可工程验证的口径：

| 目标 | 度量 | 现状 | 达标线（业界参考） |
|---|---|---|---|
| 截面预测力 | 样本外日频 Rank IC 均值 | 短线轨 ≈0（不显著） | **>0.05 且 ICIR>0.3**（A股头部量化水平） |
| 慢频信号 | 120 日截面 IC（对 510300 超额） | +0.155 ✅ | 保持 >0.10 且 t>3，逐月不衰减 |
| 组合结果 | 虚拟账本对基准超额 | 短线轨尚无 | 持续 60 日滚动超额 >0 |
| 诚实度 | 每个结论的 t 值经 ICC/DEFF 修正 | ✅ 已实现 | 保持 |

**明确不做的事**：预测明天的具体价格点位（时序点位预测在学界业界都没有稳定证据支持，
且与我们的持仓模式无关——我们赚截面排序的钱，不赚点位预测的钱）。

**止损条款（防无限空转）**：若 Phase 2~3 完成后日频因子池仍无一个过门禁，
则承认「该频率+该数据集下无显著截面信号」，把资源集中到慢频轨与事件驱动因子，
不自欺地继续调参。

## 2. 总体架构：双层循环 + 因子池状态机

```
                        ┌─────────────────────────────────────────────┐
                        │           L4 闭环控制器（新增大脑）             │
                        │  日循环调度 │ 周/月循环调度 │ 实验台账(ledger)   │
                        └───────┬─────────────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────────────────┐
        ▼                       ▼                                   ▼
┌──────────────┐      ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ L1 数据层     │      │ L2 因子层     │   │ L3 模型层     │   │  验证层(已有) │
│ 腾讯/东财/CSC │ ───▶ │ 因子注册表    │──▶│ Ridge/GBR/    │──▶│ 同一把尺:     │
│ +新源 adapter │      │ +表达式引擎   │   │ LightGBM/    │   │ rolling_     │
│ 统一进 store  │      │ 因子池状态机  │   │ 深度模型/RL/  │   │ factor_ic +  │
│               │      │              │   │ LLM 因子假设  │   │ 四关门禁      │
└──────┬───────┘      └──────────────┘   └──────────────┘   └──────┬───────┘
       │                                                        │
       ▼                                                        ▼
  data_health 画像                                    因子池: 候选→观察→准入→降级→退役
```

### 2.1 日循环（已有骨架，强化）

```
T日收盘后:  抓数据 → 算因子 → 评分 → 出报告(操作清单) → 记录预测(锁进 predictions 表)
T+1日:      实际数据到达 → 复盘(逐预测打分) → 在线调权(有门禁) → 更新因子池状态
```

关键新增：**预测先落库、后验证**。T 日的每个预测（标的、方向、预期收益分位、置信度）
当日写入 `predictions` 表，T+1 只拿这张表对账——预测内容在验证前不可修改，
这是闭环不自我污染的硬件保证。

### 2.2 周/月循环（新增）

```
每周末:  走前 ML 验证(purge+embargo) → 因子池准入/降级评审 → 模型重训对比 → 参数方案重选
每月末:  因子池整体体检(衰减检测) → 淘汰/引入决策 → 生成月度循环报告
```

### 2.3 因子池状态机（新增，核心资产）

| 状态 | 进入条件 | 退出条件 | 是否进生产评分 |
|---|---|---|---|
| candidate 候选 | 新因子（移植/挖掘/LLM 生成） | 30 日内未进观察 → 退役 | 否 |
| observing 观察 | 初检 \|IC\|>0.02 且 t>1.0 | 60 日连续观察记录 | 否 |
| admitted 准入 | **四关门禁全过**（见 §5.1） | 连续 2 个月 IC 衰减>50% → 降级 | 是 |
| degraded 降级 | IC 衰减 | 3 个月回不到准入线 → 退役 | 否（保留观察） |
| retired 退役 | 终态 | — | 否，只留台账 |

状态迁移全部写入 SQLite `factor_pool` 表，每次迁移记录：决策依据（IC 序列、样本量、
t 值、决策时间）、决策者（自动门禁 or 人工）。**防止「这个因子上个月还行」这类
无据可查的口头判断。**

### 2.4 实验台账（新增）

每次调参/换模型/换因子组合 = 一条实验记录：输入指纹（数据窗口+参数签名）、
预测结果、验证结论、是否采纳。复用 `params/` 版本留存机制，但把
「为什么这次采纳/否决」结构化入库。这是 RSI 系统的记忆——没有台账的循环
会重复试同样的死路。

6. **公告事件流**（类型化：回购/增持/业绩预告）→ 事件因子

**工程约束（v1.6 改写：原表述把「K 线类」的落盘方式写成了「一律」，与实现不符）**：
- 新源一律实现为 `src/datasources/<name>.py` 的 adapter，**统一走 `SourceGuard`**
  （限速 / 按时长熔断 / 按源熔断 / 失败分类 / 画像 / 缺失留痕），不裸调第三方库
  ——第三方库会继承环境变量代理，并绕过限速、熔断与画像；
- **K 线类**新源走 `store.upsert_kline(market, code, adjust, df, src=...)` 并复用
  `kline_is_fresh` 四条件；**截面 / 事件类**新源走各自表的幂等 upsert，并自建复用判据
  （例：`fund_flow_is_fresh` = 「上次抓取在那个交易日**收盘之后**」——与 K 线
  「跨过收盘时点必须失效」是同一条纪律：盘中快照不能当定盘值）；
- 不对称降级：现价驱动数据取不到就返回空 + `note_missing` + `data_health`，
  **绝不回落旧价**（旧价顶替当日数据等于凭空造一个不存在的观测值）；
- 每个新源进入 `data_health` 画像（成功率 / 延迟 / **归一异常逐字段计数**），
  `--db-stats` 可查。**一次抓取只占一行画像**：异常用
  `store.attach_health_anomalies` 附到那一行，另写一行会把成功率的分母翻倍，
  让一个源看起来「调用次数翻番」而真实调用次数没变；
- 事件类数据（龙虎榜/两融/解禁/退市）用独立表，不复用 K 线表结构；
- **失败分类优先于重试**：确定性失败（出口被拒、上游改列名）立即返回并跳闸，
  瞬时失败（超时、TLS 抖动）才重试。把确定性失败当噪声重试，等于把时间浪费在
  撞同一堵墙上；反过来说，用抖动去熔断会把健康源误杀 30 分钟。
- **`nodata` 不是故障**：查询本身没有结果（当日数据未公布、窗口内无记录）
  既不跳闸也不记为源故障——否则会把「今天没数据」升级成「今天之后半小时都没数据」。

### 3.2 L2 因子深挖：站在巨人肩膀上

**三层因子来源**：

**第一层：移植经典因子库（Phase 2，确定性最高）**

| 因子库 | 规模 | 可用性 | 动作 |
|---|---|---|---|
| GTJA 191 ✅ | 191 个（A股原生口径） | `wpwpwpwpwpwpwpwpwp/Alpha-101-GTJA-191` ★148 / `Daic115/alpha191`（formula 稳定） | **首批移植** |
| Qlib Alpha158 ✅ | 158 个表达式因子 | 本地 `third_party/qlib/qlib/contrib/data/handler.py:98` | **首批移植**，数据格式完全兼容 |
| Qlib Alpha360 ✅ | 360 个原始价量特征 | 同上 :48 | 摘选移植（全量计算成本高） |
| WorldQuant 101 Alphas ✅ | 101 个公式化因子，**arXiv:1601.00991** | 原论文确证；实现 `yli188/WorldQuant_alpha101_code` ★873（2019 年后未更，公式完整）；A股改造参考 `kunboyao-Bo/...-Chinese-A-share` | 第二批，需口径改造 |
| 现成脚手架 ℹ️ | Alpha158 + GTJA-191 + walk-forward LightGBM | `Haoyu-tech/astock-alpha-factor-lab`（2026-07） | 与我们 Phase 2+4 路线高度重合，**起步前先读** |

移植纪律：**所有因子过同一把尺**（`rolling_factor_ic` + ICC/DEFF 修正 + 置换检验），
不因为出身名门就免检。Alpha158 里大概率大量因子相关共线——移植时保留
`src/indicators.py` 已有的共线诊断能力，先聚类去冗余再进池。

**第二层：程序化因子挖掘（Phase 3）**

- **表达式引擎**：因子 = 算子树（ts_mean/ts_rank/corr/rank 等，Qlib 算子集够用）。
  自建轻量求值器，输入统一面板 DataFrame，输出因子值矩阵。
- **搜索方法**：先遗传规划（文献依据 ✅ 2608.01789《Towards Autonomous Formulaic Alpha
  Discovery: An Evolutionary Computation Perspective》, 2026-08），后 RL 搜索
  （AlphaGen ✅ **arXiv:2306.12964**《Generating Synergistic Formulaic Alpha Collections
  via Reinforcement Learning》）。遗传规划工程简单、可解释；RL 版本等第一层验证管线
  跑通后再上，避免一上来就搞最复杂的。
  - **搜索目标必须包含「协异性」**：AlphaGen 的原始目标是**因子集合的协同增益**，
    不是单因子最优。我们的搜索奖励函数要写成
    「加入后**组合**的边际 IC 增量」，而不是「单因子 IC 最大」——否则搜出一篮子
    变体雷同的因子（§5.3 过拟合换皮）。
  - 多样探索不足时参考 ✅ 2509.25055 AlphaSAGE（GFlowNets）；
    冷启动困难时参考 ✅ 2507.20263（从专家因子学 trajectory reward）。
- **多重检验控制**：搜索 1000 个因子表达式，5% 置换检验下必然有 ~50 个假阳性。
  必须做 **Benjamini-Hochberg FDR 控制** 或提高单因子显著性门槛（建议 t>3），
  这是因子挖掘区别于「因子碰运气」的关键。

**第三层：LLM 因子假设生成（Phase 3 后半）**

- 用法：LLM 阅读「数据字典 + 已有因子池 + 近期失效因子清单」，提出 **可回测的因子假设**
  （自然语言 → 人工/半自动翻译成表达式 → 进第一层验证管线）。
- 参考范例（✅ 均已核实）：
  - **RD-Agent** ★14748，末次 push 2026-09-23，量化场景 `rdagent/scenarios/qlib/`
    结构为 `proposal/ → experiment/ → developer/` —— 「提出假设→实验→分析」闭环的现成参照。
    **建议读它的 proposal 数据结构，但不引整个框架**（我们已有 `store.py` 与
    `rolling_factor_ic`，重造轮子成本 > 收益）。
  - **Chain-of-Alpha**（✅ 2508.06312）：LLM 链式推理挖因子的具体实现范式。
  - **FactorMiner**（✅ 2602.14670）：自进化 Agent + **技能/经验记忆**——正是我们
    §2.4 「实验台账」想做的事，其记忆组织方式值得照搬。
- **纪律**：LLM 只做假设生成器，不做信号源。LLM 输出的每个因子和搜索挖掘的因子
  走完全相同的门禁。绝不引入「LLM 说这只股票会涨」这类不可回溯信号。

**自研创新方向（结合我们的差异化数据与已验证信号）**：

1. **慢频截面增强**（在唯一显著信号上加杠杆，优先级最高）：
   质量分位 × 估值动量 × 宏观状态的三阶交互项；行业中性化后的六维残差。
2. **事件驱动因子族**：解禁前 N 日的供给冲击斜率；龙虎榜席位类型的次日衰减。
3. **Kronos embedding 因子深化**：f_kronos 目前 t=1.89 边缘显著，
   尝试 embedding 的多维度展开（而非单一相似度）。
4. **微观结构**：换手率衰减半衰期、量价背离度（`src/indicators.py` 已有原料）。

### 3.3 L3 模型迭代：沿 Qlib 路线

**模型阶梯（每级都过同一把尺，OOF 预测当因子 → `cross_section_ic` → 四关门禁）**：

| 级 | 模型 | 本地可用性 | 引入条件 |
|---|---|---|---|
| 0 | Ridge / GBR（现行验证器） | ✅ `src/ml_eval.py` | 已在跑 |
| 1 | LightGBM | ✅ Qlib contrib `gbdt.py` 可参考，依赖轻 | Phase 4 首选：正式接入 walk-forward 对比 |
| 2 | 深度时序：ALSTM / GATs / ADD | ✅ Qlib contrib 已有（pytorch_*） | 仅当 L1 数据扩展出**截面关系数据**（行业/概念图）后评估 |
| 3 | 图+概念：HIST / IGMTF | ✅ 同上 | 同上，需要概念成分数据 |
| 4 | KRNN / TRA（knoise 建模） | ✅ 同上 | 样本量与算力允许时 |
| 5 | Kronos 深化 | ✅ `third_party/Kronos` + `envs/kronos` | f_kronos 的 t>2 时升级进模型层 |

**强化学习的定位（明确边界）**：
- ✅ RL 用于**因子搜索**（AlphaGen ✅ arXiv:2306.12964）和**组合权重优化**
  （✅ 2509.01393 PPO 自适应加权；Qlib `examples/rl` 本地已核实）——搜索/优化是 RL 擅长的。
- ❌ RL 不用于「预测明天价格」——样本效率极低且不可解释。Phase 0 对 2025-08~2026-09
  前沿文献的检索结果**支持这一判断**：该方向的新工作集中在「因子表达式搜索」，
  而非「直接用 RL 预测收益序列」。

**LLM 的定位（同 3.2 第三层）**：假设生成器 + 文本数据因子化（新闻情绪/公告分类），
不做预测器。

**深度模型引入的冷静评估**：Qlib 的深度模型收益建立在其完整数据管线（分钟线/概念图/
滚动再训练）上。我们当前 5470 笔路径的面板规模，深度模型大概率过拟合。
**Phase 4 先跑 LightGBM vs GBR vs Ridge 的三方对比，深度模型等 Phase 1 数据扩展
完成后再议。**先把免费的确定性收益吃掉。

### 3.4 L4 自闭环优化：从「每日调权」到「可控实验」

现有闭环：`evaluate.py` 每日复盘 + `update_weights` 贝叶斯调权（已有 20 日门禁）。
这是日频参数层面的循环。升级方向：

**a) 预测-对账闭环硬化（Phase 5 核心）**
- `predictions` 表：T 日预测当日锁定，T+1 对账，账期用交易日不用墙钟；
- 对账维度：方向正确率、Rank IC（预测分位 vs 实际收益分位）、按置信度分层的校准度
  （说 80% 把握的事是否真有 80% 命中——**校准度是 RSI 系统最诚实的健康指标**）；
- 置信度校准差 → 自动降低该信号源的权重（不靠人盯）。

**b) 双循环调度（Phase 5）**
- 日循环：数据→因子→预测→落库→报告（~分钟级，已有）；
- 周循环：ML 走前验证→因子池评审→参数方案重选（~十分钟级）；
- 月循环：因子衰减体检→淘汰决策→月度报告。
- 调度本身只是 `run.py` 的子命令串联（`--daily/--weekly/--monthly`），不引入新框架。

**c) 循环的护栏（最重要，单列）**
- **锁盒机制**：最近 X 个月数据不参与任何调参决策，只在周循环「开盒」时用于
  一次性检验——防止同一段历史被反复用、越调越像；
- **保留期**：新参数方案需在影子模式（shadow）并行跑满 20 个交易日且不输现役方案，
  才准替换生产参数——`model_select` 已有 walk-forward，升级为影子并行；
- **回归测试**：每次代码改动跑 `tests/`（幂等、缓存一致性、账本对账已有），
  加因子池状态机迁移的测试。

**d) 论文参考（Phase 0 已完成）**

11 篇前沿文献已核验归档，完整清单见 `docs/research/phase0_verification.md §4`。

## 5. 反自欺纪律清单（循环系统的宪法）

### 5.1 四关门禁（因子/模型从验证进生产的唯一通道，全项目统一）

1. 样本外 IC 更高（vs 现役基准，同数据同口径）；
2. ICIR 不低于现役；
3. 尾部守卫：去掉 \|IC\| 最大 10% 的截面后优势仍在（防单日驱动）；
4. 置换检验显著（p≤0.10）+ **FDR 修正后仍显著**（新增，批量挖掘时强制）。
5. **v1.1 新增 · 边际增量关**：对**已准入因子池**的边际贡献为正——用加入后的组合
   Rank IC 增量衡量，而非单因子绝对 IC。依据：AlphaGen 的目标是协同集合而非单因子最优；
   不设此关会把「换个写法的新因子」反复判为有效（§5.3 过拟合换皮）。

### 5.2 已付学费的教训（全部硬化为代码约束，不许靠记忆）

| 教训 | 硬约束 |
|---|---|
| 重叠窗口泄漏（IC 虚报 12 倍） | `date(train)+horizon+embargo ≤ date(test)`，任何滚动评估先量「截面间距 vs 持有期」 |
| 名义 N 虚高（ICC≈0.36） | 一切 t 值过 ICC/DEFF 修正 |
| 参数写回链路断裂 | 「机制测试通过」≠「代码在用机制」，每次接线走 `check_run_wiring` 思路核产物清单 |
| 账本重复写入 | 幂等 upsert，(date,code) 去重 |
| 确定性错误当偶发错误重试 | 失败分类（rc=102/401/403 立即返回），窗口降级是语义降级 |
| 显示精度 < 存储精度 | 存 round(x,8)，显示不低于存储精度 |
| 缓存静默复用 | 内容寻址键 + 命中/未命中都打日志 |
| 休眠冻进程 | 长任务 `caffeinate -i` 包裹，进度看日志时间戳不看 etime |

### 5.3 循环系统特有的新风险

| 风险 | 对策 |
|---|---|
| **多重检验**（挖掘 1000 个因子必有假阳性） | FDR 控制 + 单因子 t>3 门槛 + 置换检验 |
| **数据窥探**（同段历史反复调参） | 锁盒机制 + 影子模式保留期 |
| **幸存者偏差**（退市股消失） | ✅ **数据已落地**：`delisted` 表（沪 153 + 深 208 只，含退市日）。因子评估面板必须纳入历史退市标的——`tests/offline_datasources.py` 保证清单可回补、幂等 |
| **循环自我强化幻觉**（用模型的输出训练模型） | 预测当日锁库不可改；验证只用真实行情，绝不用模型产出 |
| **过拟合换皮**（同一信号换个表达式反复进门禁） | 因子注册表登记算子树哈希，与已准入因子相关系数 >0.8 的新因子视为冗余 |
| **上游算好的事件后收益混进特征**（新，Step 3） | 事件类表的列映射表里**不含**「上榜后 N 日」「解禁后 20 日涨跌幅」——不是过滤，是根本没有映射；自检里有一条断言专门守这个 |
| **非等价降级**（新，Step 4 实测） | 降级链有一档不是「同一件事的另一个源」，而是**规模小一个数量级的静态池**：腾讯档给 ETF 62 只 / 港股 47 只，全市场是 1693 / 2811 只。东财成功率仅 9%~15%，所以多数日子的候选池其实来自那份固定名单——**报告完全看不出异常**，只是机会集合被悄悄缩小了。<br>对策：① 注入新浪全量源（1693/2806 行，实测可达）；② `rank_snapshot.src` 补列落库（原先 `upsert_rank_snapshot(..., src=...)` **收下形参却没有这一列**，标注被静默丢弃，导致「长期在降级」根本无法被查询发现）；③ 档位顺序可配置，**是否把新浪提到腾讯之前属策略口径变更，单独确认** |

## 版本记录

- **v1.6 (2026-10-01)**：Phase 1 全面审计（收口）。
  逐条核对 §3.1 工程约束与 §4 Phase 1 验收标准后，**发现并修掉 4 处不一致**
  （都不是「功能没做」，而是「文档写了但没做到」或「同一个东西两个名字」）：
  1. **「字段缺失率」从未落地** —— 画像只有成功率/延迟。已给 `data_health` 加
     `anomalies`（归一异常的**逐字段计数**，JSON），三个适配器在归一后附加，
     `--db-stats` 新增「最近的归一异常」段。这一列解决的正是成功率看不见的那种坏：
     抓取成功、某字段悄悄变 NULL，成功率仍是 100%（schema v8）。
  2. **同一个档两个源名** —— tencent 在 `rank_snapshot.src` 里叫 `tencent_fallback`、
     在 `data_health` 里叫 `tencent_quote_list`，跨表按源回溯直接对不上。已统一。
  3. **配置写了不生效** —— 新浪档（Step 4 新接）从未调用 `configure`，
     事件类缺 `breaker_ttl_sec` 透传。已全接通，并加断言「三个源的 configure
     必须吃下 config.json 的全套键」——少一个参数就会静默退回内置默认值。
  4. **`--spot-probe` 会改动生产状态** —— 它删东财熔断标记，且失败时还会
     `_em_mark_blocked` 刷新 mtime（反复跑探针等于把 30 分钟熔断一直续期）。
     已改为「忽略而不修改」，并加断言守住（这个断言在修好之前是红的）。
  5. **新增的 anomalies 列差点自己变成噪声** —— 归一函数同时返回「统计信息」与
     「异常」，第一版把 `rows`（行数）也记成了异常，于是**每一次成功抓取都显示
     「有异常」**；收紧一次后 `dup`（上游分页重叠、我们按主键去重、不丢信息）
     又让龙虎榜每天亮一次。最终把判据写死进 `base.anomaly_payload`：
     **只有「有东西被丢了、或被改成了 NULL」才算异常**——常亮的告警等于没有告警。
     自检里补了两条：干净数据不得产生异常记录；真异常必须由适配器写进画像
     （「机制测试通过 ≠ 代码在用机制」，要查调用点）。
  6. **两融的「已在库」按日期判断 → 会永久丢深市数据**（在生产数据里发现的）：
     沪、深两个接口各自独立失败（实测 10-01 那天沪市拿到 09-30、深市被 reset），
     而补漏判据是「这个日期有没有数据」——沪市一成功，这天就被判成「已齐」，
     深市缺口**永远不会被补**；两融明细是逐日累积的，缺的那天就是永久缺。
     已改为**按交易所判断齐备**（`store.margin_dates(market, exchanges)`），
     并加断言「半齐不算齐」。实测该修复已在运行中生效：下一次运行就把 09-30
     判成「待抓」而不是「已在库」。
     顺带发现**两所的公布节奏也不同步**（实测 09-30：沪市已公布、深市还没），
     所以「按交易所判断」不只是防接口抖动，也是防两所发布时差的必需——
     09-30 的深市会在其公布后的那次运行里自动补上（明细可回补，不会永久缺）。
